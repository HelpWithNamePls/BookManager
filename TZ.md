# Функциональные требования

Система должна выполнять следующие функции:


| Функция | Что делает |
| --- | --- |
| Добавление книги | Пользователь вводит id, автора, год издания и общее кол-во экземпляров. Система проверяет уникальность id и добавляет запись в массив books.|
| Просмотр всех книг | Система перебирает массив books и выводит таблицу: id, название, автор, год, доступно/всего |
| Просмотр всех пользователей | Выводит таблицу пользователей. Номер,имя,роль |
| Поиск по автору | Вводится фамилия и система ищет соответствия и выводит все совпадения  |
| Поиск по названию | Работает аналогично поиску по автору |
| Выбор книги по id | Вводят id система находит книгу и выводит ее информацию|
| Выдача книги | Пользователь вводит id книги и табельный номер читателя. Происходит проверка что они оба существуют и книга доступна. Если все условия совпали книга удаляется, а общее кол-во доступных книг уменьшается|
| Возврат книги | id книги, табельный номер читателя. Система ищет запись в журнале issued - удаляет ее и увеличивает кол-во доступных книг |
| Сохранение и загрузка | при старте программа читает файл с данными, а при выходе записывает текущее состояние в этот файл |

# Пользовательские сценарии

## Сценарий 1 Добавление новой книги

1. Пользователь запускает программу.
2. Она загружает данные из файла(если он есть).
3. Пользователь выбирает пункт 1.
4. Система запрашивает данные.
5. Происходит проверка уникальности id. Если он не уникален - выводит ошибку и возвращает в меню
6. Книга добавляется в массив и выводит подтверждение
7. Пользователь выбирает пункт 0 для выходаю
8. Система сохраняет данные в файл(а если его нет создает и сохраняет) и завершает работу


## Сценарий 2 Поиск и выдача книги

1. Пользователь выбирает пункт 4. Поиск по автору и вводит "Булгаков"
2. Выводится все книги с указанием доступных экземпляров
3. Пользователь запоминает id нужной книги
4. Выбирает пункт 8, вводит id и номер читателя
5. Система проверяет есть ли книга и читатель, доступна ли книга
6. Книга доступна. Уменьшает значение на 1, добавляет метку
7. При выходе файл сохранения изменяется

## Сценарий 3 Возврат книги

1. Читатель возвращает книгу с ID 101.
2. Пользователь выбирает пункт 9, вводит ID 101 и табельный номер 1001.
3. Система ищет запись в issued по паре (bookId, userTab).
4. Если запись найдена — удаляет её, увеличивает available на 1, выводит подтверждение.
5. Если записи нет — выводит ошибку «Запись о выдаче не найдена».
6. Пользователь выбирает пункт 2, чтобы убедиться, что счётчик available вернулся к исходному значению.

# Технические ограничения

Платформа: Windows

Кодировка: UTF-8 для исходного файла и консоли. На Windows требуется SetConsoleOutputCP(65001) и сохранение файла в UTF-8 с BOM.

Объём данных: до 1000 книг и 500 пользователей без потери производительности (ограничение vector не жёсткое, но для учебного проекта этого достаточно).

Хранение: только локальный текстовый файл, без базы данных и сетевого взаимодействия.

Многопользовательский режим: отсутствует. Программа рассчитана на одного оператора за одним компьютером.

Зависимости: только стандартная библиотека C++; сторонние библиотеки не используются.

Сборка: один исполняемый файл, без установки.
